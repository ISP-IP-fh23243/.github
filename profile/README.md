<h2>买之前先把需求写成一句话</h2>
<p>采购最容易犯的错是先去逛套餐，看见「八核十六G、五条住宅IP」觉得划算就下单，结果用起来才发现根本不需要这么多核，真正缺的是地址稳定性和更换服务。所以第一步不是比价，而是把需求压缩成一句话：我要给几个长期账号，配几条固定地址，在哪个国家，每天大概跑多少流量。</p>
<p>这句话里四个变量定下来，套餐范围就缩小到两三款，比价才有意义。四个变量写不清，说明需求还没想清楚，这时候买什么都是在赌。</p>

<h2>地址怎么定：先算「不可共享」的数量</h2>
<p>把账号列出来，标注哪些必须独占地址（涉及资产、需要长期登录），哪些可以共用。前者数量就是你需要的独享地址数，后者可以合并到共享资源。多数团队算完会发现，真正需要独享的只有三五个，其余都是「想当然要独立」。</p>
<p>另外确认一件事：追加地址是否同段。同段追加归属一致，适合需要多个身份的团队；跨段追加便宜但一致性差。采购时把这句话写进需求，供应商就不容易拿跨段资源充数。</p>

<h2>询价要问的六个问题</h2>
<p>一、地址是独享还是共享，共享的话同一地址最多几人使用。二、带宽是保证还是峰值，晚高峰是否限速。三、地址不可用时免费更换几次，响应时间多久。四、是否包含初始部署与后续巡检。五、是否同段追加，追加单价多少。六、能否先试用，试用期能否做完整验收。</p>
<p>这六个问题里，第三和第六最能筛出靠谱的供应商。愿意明确写清更换政策的，通常对自己的资源有把握；肯给试用期的，说明不怕你验。反过来，对这些问题含糊其辞、只催下单的，后面大概率会扯皮。</p>

<h2>价格怎么比：比总成本，不比月费</h2>
<p>月费只是固定支出，还有一块是风险成本：地址不稳导致的停工、迁移、账号环境变更。一条便宜三成但每月要迁移一次的地址，实际成本远高于稳定但贵三成的方案。</p>
<p>比较方法很简单，按三个月为一周期算：月费乘三，加上预估的故障处理时间折算成本，加上可能的迁移损失。三项加总再横向比，结论往往跟只看月费完全不同。</p>

<h2>下单到上线的流程</h2>
<p>第一步，确认订单参数并留档，尤其是地址段、带宽承诺、更换条款。第二步，拿到资源后先做独立验收：查 ASN 与归属、测出口、测带宽、测稳定性。第三步，验收通过再迁移业务，不要一边验一边用。第四步，把参数与验收结果写进资产表，标注启用日期。</p>
<p>第三步是最容易被跳过的。很多人拿到资源就直接登录主账号试，一旦地址有问题，账号已经留下了一次异常登录记录。正确做法是先用无关的小号或纯浏览流量试，确认环境干净再上主账号。</p>

<h2>常见坑</h2>
<p>坑一：把「住宅」当成唯一标准，忽略了独享程度。住宅段共享给几十人用，状态可能比干净机房还糟。坑二：只看首月优惠，忽略续费价格。坑三：没有书面约定更换政策，出问题时对方一句「正在处理」拖上一周。坑四：地址给的是不同网段，申诉时才发现归属不一致，已经来不及换。</p>

<h2>常见问答</h2>
<h3>第一次买，买几条地址合适</h3>
<p>按「必须独享的账号数」买，宁可少买、后续同段追加，也不要一次买多导致用不完。用不完的地址闲置不影响使用，但会拉高单位成本。</p>
<h3>能不能只买地址不买服务器</h3>
<p>可以。地址通过代理方式接入，本地或自有服务器都能用。这种方式开通快、成本低，适合已有设备的团队；缺点是依赖服务端稳定性，出问题时只能等。</p>
<h3>怎么判断供应商给的地址是不是真的住宅</h3>
<p>查 ASN。地址挂在宽带运营商名下才算住宅段，挂在云厂商名下就是机房。这项查询免费公开，任何宣传词都改变不了结果。</p>
<h3>试用期应该重点测什么</h3>
<p>测三件事：地址是否真的固定、晚高峰速率、连续访问是否断流。前两项决定能不能用，第三项决定能不能长期用。只测「能不能打开网页」，等于没测。</p>
